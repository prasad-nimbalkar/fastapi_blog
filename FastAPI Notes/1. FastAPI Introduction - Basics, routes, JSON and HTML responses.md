## 1. What is FastAPI?

- A modern, fast Python web framework for building APIs.
- Built on top of **Starlette** (for web handling) and **Pydantic** (for data validation).
- Key features:
  - **Automatic API documentation** (Swagger UI & ReDoc) — generated from code, no extra config.
  - **Built-in data validation** using Pydantic models.
  - **Async support** — supports both `async def` and regular `def` route functions.
  - Very fast performance — comparable to Node.js and Go frameworks.

> **Interview Tip:** FastAPI is popular because it combines speed, modern Python type hints, auto docs, and async support — all in one framework.

## 2. Installation & Setup

### Recommended install (with standard extras)

```bash
pip install "fastapi[standard]"
```

### What `fastapi[standard]` includes

- `fastapi` — the framework itself.
- `uvicorn` — the ASGI server that runs the application.
- `fastapi CLI` — the command used to start the dev server.

> **Important:** Always install with `[standard]` unless you have a specific reason not to — it gives you everything needed to run FastAPI out of the box.

## 3. Creating a Basic Application

```python
from fastapi import FastAPI

app = FastAPI()
```

- `FastAPI()` creates the application instance.
- All routes are defined on this `app` object.
- FastAPI **automatically converts** Python dicts and lists to JSON responses.

---

## 4. Routes & Decorators

```python
@app.get("/")
def home():
    return {"message": "Hello World"}
```

- Routes use **decorators** like `@app.get()`, `@app.post()`, `@app.put()`, `@app.delete()`.
- The decorator defines the **HTTP method** and **URL path**.
- The function below the decorator is executed when that route is called.
- Returning a **dictionary** → FastAPI automatically converts it to **JSON**.

### Creating an API endpoint with data

```python
posts = [
    {"id": 1, "title": "Post One", "content": "Content here..."},
    {"id": 2, "title": "Post Two", "content": "More content..."},
]

@app.get("/api/posts")
def get_posts():
    return posts  # list of dicts → returned as JSON array
```

> **Interview Tip:** FastAPI uses Python decorators for routing — same pattern as Flask, but with added type validation and auto docs.

## 5. Running the App

```bash
# Development mode (with auto-reload)
fastapi dev main.py

# Production mode (optimized for performance)
fastapi run main.py
```

| Mode | Command | Use Case |
|---|---|---|
| Development | `fastapi dev main.py` | Local development — auto-reloads on file changes |
| Production | `fastapi run main.py` | Deployed/production environment |

> **Important:** `fastapi dev` includes **auto-reload** — the server restarts automatically when you save code changes. Always use `dev` locally and `run` in production.

## 6. Automatic API Documentation

FastAPI auto-generates **two** interactive documentation UIs — no configuration needed.

| URL | UI | Description |
|---|---|---|
| `/docs` | Swagger UI | Interactive, try-out API docs |
| `/redoc` | ReDoc | Cleaner, read-only modern docs view |

### What the docs provide

- Lists all API endpoints with their HTTP methods and paths.
- Lets you **try out** API calls directly in the browser.
- Shows request parameters, response body, and a ready-to-use `curl` command.

> **Common Question:** *"How does FastAPI generate documentation automatically?"*
> FastAPI reads your route decorators and Pydantic models at startup and builds an OpenAPI schema, which Swagger UI and ReDoc render as interactive docs.

## 7. Returning JSON vs HTML

### Returning JSON (default)

```python
@app.get("/api/posts")
def get_posts():
    return posts  # automatically serialized to JSON
```

### Returning HTML

```python
from fastapi.responses import HTMLResponse

@app.get("/", response_class=HTMLResponse)
def home():
    return f"<h1>{posts[0]['title']}</h1>"
```

- Import `HTMLResponse` from `fastapi.responses`.
- Add `response_class=HTMLResponse` to the route decorator.
- Return an HTML string from the function.

> **Interview Tip:** FastAPI supports dual-mode — JSON routes for API/programmatic access, HTML routes for browser users. Both can share the same underlying data.

## 8. Stacking Decorators & `include_in_schema`

### Stacking decorators (multiple URLs → same function)

```python
@app.get("/", response_class=HTMLResponse, include_in_schema=False)
@app.get("/posts", response_class=HTMLResponse, include_in_schema=False)
def home():
    return f"<h1>{posts[0]['title']}</h1>"
```

- You can stack multiple `@app.get()` decorators on one function.
- Both `/` and `/posts` will execute the same function.

### `include_in_schema=False`

- Hides the route from `/docs` and `/redoc`.
- The route still works in the browser — it just doesn't appear in API documentation.
- Use this for **HTML page routes** to keep API docs clean (only JSON endpoints should appear there).

> **Important:** HTML routes are for humans browsing the site. API docs are meant for developers consuming JSON endpoints. Use `include_in_schema=False` to maintain this clean separation.

## 9. Common Interview Questions

**Q: What is FastAPI and what makes it different from Flask or Django?**
> FastAPI is a modern Python web framework with built-in data validation (Pydantic), automatic API documentation (OpenAPI/Swagger), and native async support. Flask lacks these built-in features; Django is a full-stack framework with more overhead.

---

**Q: What does `fastapi[standard]` install?**
> It installs the FastAPI framework, Uvicorn (the ASGI server), and the FastAPI CLI tool used to run the application.

---

**Q: What is the difference between `fastapi dev` and `fastapi run`?**
> `fastapi dev` is for development — it enables auto-reload on file changes and provides debug output. `fastapi run` is for production — it is optimized for performance without the dev overhead.

---

**Q: How does FastAPI handle JSON serialization?**
> FastAPI automatically converts returned Python dictionaries and lists into JSON responses. You don't need to call `json.dumps()` or set headers manually.

---

**Q: What is `include_in_schema=False` used for?**
> It hides a route from the auto-generated API documentation (`/docs` and `/redoc`). The route still works — it just won't appear in the docs. Useful for HTML page routes that aren't part of the public API.

---

**Q: What are `/docs` and `/redoc`?**
> Both are auto-generated API documentation UIs. `/docs` uses Swagger UI (interactive, allows you to test endpoints). `/redoc` uses ReDoc (modern, read-only view). Both are generated from your code — no manual documentation needed.

---

**Q: Can you use `async def` and regular `def` in the same FastAPI app?**
> Yes. FastAPI supports both. Regular `def` routes are run in a thread pool so they don't block the event loop. Use `async def` when your function performs I/O-bound async operations (e.g. async database calls).

## 10. Common Mistakes & Pitfalls

> **Pitfall:** Returning a string instead of a dict — FastAPI won't auto-serialize it as JSON; it just returns a plain string response.

> **Pitfall:** Using `fastapi run` in development — you lose auto-reload, which slows down your workflow.

> **Pitfall:** Forgetting `response_class=HTMLResponse` when returning HTML — FastAPI will wrap your HTML string in JSON quotes.

> **Pitfall:** Not using `include_in_schema=False` on HTML routes — your API docs become cluttered with page routes that aren't part of the API.

> **Pitfall:** Selecting the wrong Python interpreter in your editor — FastAPI imports will show as unresolved even if the package is installed in the virtual environment.

---

## 11. Best Practices

- Always install with `fastapi[standard]` for a complete setup.
- Use `fastapi dev` during development and `fastapi run` in production.
- Keep API routes (JSON) and page routes (HTML) clearly separated.
- Use `include_in_schema=False` on all HTML/page routes to keep `/docs` clean.
- Return dictionaries or lists from route functions — FastAPI handles JSON conversion automatically.
- Use meaningful route names and organize routes logically (e.g. `/api/posts` for API, `/posts` for HTML page).
- Never hardcode data in production — replace dummy data with a proper database (e.g. SQLAlchemy + PostgreSQL).
